# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Virtual Tavern is a private, self-hosted website for playing realtime party games with friends. It hosts eight games: **Codenames**, **Enigma** (a team code-breaking game; only ever call it Enigma), **Echo** (a cooperative one-word-clue game; only ever call it Echo) and **Masquerade** (a hidden-spy location game; only ever call it Masquerade) in `packages/games/`, and **Reverie** (a picture-clue storytelling card game whose art lives in private storage; only ever call it Reverie), **Hoodwink** (a bluffing trivia game; only ever call it Hoodwink), **Royal Post** (a courtship card game; only ever call it Royal Post), Masquerade's back-room edition and **Nightfall** (a one-night werewolf-style hidden-role game; only ever call it Nightfall) in the password-gated back room, `packages/private-games/`. It has no accounts: players join rooms through unguessable links, and only admins (who sign in with a password from the environment) can edit word lists and set the back-room password.

## Toolchain

- Node and pnpm are pinned by **Volta** in the root `package.json` (`volta` field). There is no `.nvmrc`. The `packageManager`, `engines`, the CI `setup-node` (`node-version-file: package.json`) and the `Dockerfile` `NODE_VERSION`/`PNPM_VERSION` args must all stay in sync with that pin.
- Shell commands need `export PATH="$HOME/.volta/bin:$PATH" VOLTA_FEATURE_PNPM=1`, or Volta can't find pnpm.
- pnpm is held at **11.x**. pnpm 12 ships a native binary that Volta's launcher can't run.
- TypeScript is held at **~6.0** because typescript-eslint supports `<6.1` only.
- pnpm 11 blocks dependency build scripts. Any dependency that needs one must be listed under `allowBuilds` in `pnpm-workspace.yaml`; `pnpm approve-builds <pkg>` adds it.
- Never pass `-g` through `pnpm` (`pnpm e2e -g x`): Volta takes it as "global". Use `pnpm exec playwright test --grep x`.

## Commands

```sh
pnpm dev                 # server :3000 (tsx watch) + web :5173 (Vite proxies /api, /healthz, /socket.io)
pnpm lint                # ESLint (typed) over the whole repo, e2e included
pnpm typecheck           # root tsconfig (configs + e2e) then tsc --noEmit in every package
pnpm test                # Vitest across all workspace projects
pnpm format:check        # Prettier; `pnpm format` to fix
pnpm build               # tsup bundles the server, Vite builds the web app
pnpm e2e                 # Playwright against the production build: run `pnpm build` first

pnpm vitest run apps/server/src/realtime.test.ts   # one file
pnpm vitest run -t "server restart"                 # by test name
pnpm vitest run --project codenames                # one workspace project
SCREENSHOTS=1 pnpm exec playwright test e2e/screenshots.spec.ts   # UI screenshots -> test-results/shots
docker compose up --build                          # production container locally (see docs/deployment.md)
```

To check workflow and shell edits, run `docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:latest` and `docker run --rm -v "$PWD":/mnt koalaman/shellcheck:stable scripts/deploy.sh`. Third-party actions are pinned to commit SHAs, with the version in a trailing comment.

## Architecture

The repo is a pnpm monorepo, with ESM and strict TypeScript throughout.

- **Imports use explicit `.ts`/`.tsx` extensions.** Workspace packages export TypeScript source and are never compiled on their own: Vite bundles them for the web, and tsup bundles them into `apps/server/dist` (`noExternal: /^@vt\//`, which is why they are server *dev*Dependencies).
- **Game plugins** (`packages/games/<id>`, private ones in `packages/private-games/<id>`) implement `GameDefinition` from `packages/game-sdk/src/types.ts`. The step-by-step guide, including the member list, lobby and timer hooks, is `docs/adding-a-game.md`; the invariants are:
  - Logic is pure and its state JSON-serialisable. Randomness comes only from `ctx.rng`, time from `ctx.now`, and word lists from `ctx.content`.
  - `reduce` **returns** a `GameError` rather than throwing.
  - `view` must strip hidden information per viewer. This is the security boundary.
  - Each game package exports `/logic` and `/ui`; the UI takes `GameUiProps` (`packages/game-sdk/src/ui.ts`) and is built from `@vt/ui` primitives (`WordListPicker`, `TimerSettings`, `Modal`, `Countdown`), with `wordPool` from `@vt/game-sdk`.
  - Registries: `apps/server/src/games/registry.ts` and `apps/web/src/games/registry.ts` (private games: `apps/web/src/games/private.ts`).
  - **Enigma** (`packages/games/enigma`): votes only resolve when every eligible teammate has picked the same code and pressed Lock in. Team chat and shared notes live in game state and are filtered per team by `view()`. On phones the play screen is split into Play / Clues / Chat tabs (`EnigmaGame.tsx`); design every game screen to fit a phone viewport without long scrolling.
  - **Echo** (`packages/games/echo`): clue and guess matching uses `normaliseWord`/`wordKey` from `packages/game-sdk/src/words.ts` (case, accents, punctuation, plurals and simple stems). `view()` hides the secret word from the guesser until the reveal and sends them only the surviving clues, without authors or the cancelled ones (just `cancelledCount`). The UI pre-checks clues with the engine's `clueProblem` so refusals show inline.
  - **Masquerade** (`packages/games/masquerade`): players talk out loud and the app never tracks the asking. It deals (locals get only the location, the spy gets nothing; two spies at 7+ is a host option), names who starts (rotating), runs the round clock, then one secret vote (when the clock ends or everyone is Ready; 45 s, non-voters abstain). `namedBy` names a player only if at most as many players as there are spies have as many votes, so ties name nobody. Only a caught spy guesses the location (30 s). The logic is `defineMasquerade(config)`, so the pack is a parameter; the public pack (`src/content/`) is self-written: never copy the commercial game's locations, and never name that game. `view()` sends the location only to locals, hides the spies until the reveal (caught spies show in the guess stage) and sends only `votedCount`/`myVote` until the vote resolves. The UI (`MasqueradeBoard`, with a `LocationDisplay` adapter) has Play / Locations / Ideas tabs; board marks live in localStorage per table and deal.
- **Rules guides:** each game's `GameGuide` (`src/logic/guide.ts`) renders on `/rules/:gameId` and in the in-room rules drawer, through `apps/web/src/components/GuideView.tsx`. Update the guide in the same change as any rule change.
- **Room host** (`apps/server/src/rooms/manager.ts`):
  - It is game-agnostic. better-sqlite3 is synchronous, so each call runs to completion and actions on a room are naturally serialised.
  - Every accepted change goes through `commit()`, which bumps `version`, persists through `RoomStore` (an optimistic version check), re-arms the game's deadline timer, and emits `changed`.
  - `realtime.ts` turns `changed` into a per-socket `room:state` snapshot holding that player's own `view()` plus `serverNow`, which clients use to correct countdowns for clock skew.
  - Rooms load lazily from SQLite, and timers re-arm on load, so play survives restarts.
  - A host who is offline for `HOST_AWAY_MS` hands the role to an online player.
- **Identity:** the browser keeps a secret `playerToken` in localStorage, and the server derives the public player id as `sha256(token)`, so ids shown to others can't be used to impersonate anyone.
- **Persistence:** the Drizzle schema is in `apps/server/src/db/schema.ts`. After changing it, run `pnpm --filter @vt/server db:generate`; migrations in `apps/server/drizzle/` run when the new container starts. A failed deploy rolls back the image but not the schema, so every migration must be backward-compatible with the previous release (additive only; rename or drop in a later release). The `pre-deploy-<version>-*.db` backup is the manual restore point. Word lists are stored as a JSON array per list, with a `games` JSON array of the games that offer it (games set `usesWordLists`); `WordListRepo.forGame(id)` is the per-room `ctx.content`, so a room only sees lists tagged for its game. An `enabled` flag (admin switch, `PATCH /api/admin/word-lists/:id`) hides a disabled list from `forGame` (lists and words) and the public `/api/word-lists`; admins still see it. The self-authored starter list (`starter-words.ts`) is seeded only when no lists exist.
- **Question decks** (`question_decks`, `QuestionDeckRepo` in `apps/server/src/question-decks.ts`) hold trivia questions for games that set `usesQuestionDecks`, mirroring word lists: a `games` array (default `["hoodwink"]`; the admin API accepts only registered games that set `usesQuestionDecks`), an `enabled` switch, and `forGame(id)` merged into the per-room `ctx.content` (`roomContent`). Each question is `{prompt, answer, alternates, sources, adult, tags, decoys?}`, with ids `<deckId>:<index>`; the rules live in `packages/protocol/src/questions.ts` and are repeated in `scripts/import-question-decks.mjs`. **The decks are private content: never commit them** (not even as fixtures; tests use small made-up decks). They live only in the production database, are imported with `scripts/import-question-decks.mjs` (see `docs/deployment.md`) and backed up from `/admin`. Only private (back-room) games use them: deck summaries are served at `GET /api/backroom/question-decks/:gameId`, which answers 404 unless the browser is unlocked and the game is private with `usesQuestionDecks`. No public endpoint returns deck names, and answers, sources and decoys never appear in an HTTP response except the admin detail and export (rooms get answers and decoys through `ctx.content.questions()`, and `view()` must hide them).
- **Built-in word packs** are `apps/server/word-packs/<slug>.json` (`{slug, name, description, words}`; file name must match the slug; entries ≤ 20 chars, ≥ 100 unique words). On startup `WordListRepo.seedPacks` adds any pack whose slug isn't in `seeded_packs` yet, exactly once, so admin edits and deletions stick. Changing a shipped pack's file does not update existing databases; add a new slug instead. `word-packs.test.ts` validates every pack file.
- **Admin stats** (`apps/server/src/stats/`): the room manager reports every change to an optional `RoomObserver`; `StatsRecorder` turns that into flat events (game start and end are detected generically from `phase`), buffers them and writes every 2 s. A failing observer is logged and never reaches play. Games may add a pure `insights(before, after, action, by)` returning `InsightEvent`s (clues, guesses, outcomes), which feed the per-game figures and fun facts in `stats/figures.ts`. Storage sits behind the `StatsStore` (write) and `StatsQueries` (read) interfaces, so a column store can replace SQLite later. Rollups and raw-day queries share one aggregation (`stats/aggregate.ts`), so a rolled-up day must read exactly like its raw events (tested). Routes are `/api/admin/stats/*` (`routes/stats.ts`), typed by `packages/protocol/src/stats.ts`, the single source of truth for both sides: `percent` figures are 0–100, and responses name every game they mention (`games`, private ones included) so the page needn't unlock the back room. The event props each game emits must match what `figures.ts`/`aggregate.ts` read (Echo credits "the echo" from `match {a, b}` events); `routes/stats.test.ts` plays real Codenames and Echo games to keep them in line. The Words card offers only the word kinds each game reports (`apps/web/src/stats/word-kinds.ts`, with per-game labels such as Hoodwink's "Lies"), and chart colours come from a fixed per-game order in `apps/web/src/stats/palette.ts`: append new games at the end so existing colours never shift. The page is `/admin/stats` (`apps/web/src/pages/StatsPage.tsx`, `apps/web/src/stats/`), a lazy chunk with ECharts split into its own `echarts` chunk; its e2e specs serve the typed fixtures (`stats/fixtures.ts`, kept in step with the server's figures) except one that plays a real Echo card. Retention, export and reset are covered in `docs/deployment.md`.
- **Config:** `apps/server/src/config.ts` reads env vars, and its default paths resolve the same way from `src/` and `dist/`. Admin auth (`admin-auth.ts`) is a signed, httpOnly cookie bound to the current password, and login is rate-limited (keyed on `cf-connecting-ip` when the peer is a local address such as the tunnel, otherwise on the peer's own address). Errors leave through `setErrorHandler` in `app.ts` as `{ error: { code, message } }`; 5xx bodies never carry the cause.

## Testing notes

- Codenames rules tests use `harness()` and `startedGame()` from `packages/games/codenames/src/logic/test-utils.ts`, which give a seeded, deterministic game with fixed seats.
- Server tests use `testApp()` and `connect()` from `apps/server/src/test/helpers.ts`. `realtime.test.ts` plays a full game across a server restart, and `manager.test.ts` covers timers and host hand-off with fake timers.
- e2e specs fail on any uncaught browser error (`pageErrors` in `e2e/codenames.spec.ts`).
- All e2e specs share one server. Specs that change server-wide state (the back-room password, question decks) run one at a time in the `back-room` Playwright project (`SHARED_STATE` in `playwright.config.ts`); add new ones there, and delete what they create in an `afterEach`/`finally`.
- React effects must use block bodies. Newer Chrome returns a Promise from `scrollIntoView()`, and an expression-bodied effect passes that to React as its "cleanup", which crashed the board.

## Releases and deploy

- PRs are squash-merged, so the PR title is the commit and must follow Conventional Commits (enforced by `pr-title.yml`).
- CI fails on flaky e2e tests (`failOnFlakyTests`): a test that only passes on retry is a bug to fix. Wait for UI state with `expect.poll` or web-first assertions rather than one-off `isVisible()` checks.
- release-please (`release.yml`) runs only after CI succeeds on `main` (`workflow_run`), and keeps a Release PR open. Merging it tags `vX.Y.Z`, publishes a multi-arch image to GHCR, then calls `deploy.yml`, which needs approval through the `production` environment. That job joins the tailnet (Tailscale OAuth, `tag:ci`), SSHes to the server and runs `scripts/deploy.sh <version>`: back up the DB, pull, wait for health, and roll back automatically on failure.
- Running `deploy.yml` by hand redeploys or rolls back to any version. One-time server, Cloudflare and GitHub setup is in `docs/deployment.md`.

## Back room (private games)

- Games with `access: 'private'` (in `packages/private-games/`) are only listed, created, joined and played by browsers holding a current `vt_backroom` unlock. The admin sets one shared password in `/admin`; changing it, or **Sign everyone out**, bumps a version that invalidates every unlock (`apps/server/src/backroom.ts`). Sockets re-check the cookie on every action.
- **Never commit protected assets.** The repo is public, and `*.zip` and `private-assets/` are git-ignored. Stage files by explicit path, never `git add -A`. Art and card files live in a private Cloudflare R2 bucket; the server streams them to unlocked players at stable URLs (`/api/backroom/assets/:gameId/*`, `Cache-Control: private, max-age=1y, immutable`, so browsers keep them and the CDN never does) along with each game's `manifest.json`. Upload with `scripts/r2-upload.mjs <gameId> <folder>`, which reads credentials from `~/.config/virtual-tavern/r2-upload.env`.
- Private game UIs are registered in `apps/web/src/games/private.ts`. Vite builds them into `/backroom-assets/`, which the server serves only to unlocked browsers, with `Cache-Control: private, no-store`. Use `ProtectedImage` from `@vt/ui` for their art.
- **Reverie** (`packages/private-games/reverie`) is the first private game and the template for new ones: card art comes from R2 (`cards/<nnn>.jpg`, set names and the card back from `manifest.json`), while card-number ranges per set are hard-coded in `CARD_SETS` so the pure logic needs no I/O. Without asset storage (tests, dev) cards render as numbered placeholders, so the game stays testable.
- **Hoodwink** (`packages/private-games/hoodwink`) is a bluffing trivia game: everyone writes a fake answer to a strange true question, then votes for the truth. Its questions come only from the private question decks (`usesQuestionDecks`), never from the repository. The lobby lists decks from `ctx.content.questionDecks()`, kept in game state and refreshed on every lobby action, so deck names only reach players in an unlocked room. A lie matching the answer or an alternate under `wordKey` is refused, identical lies merge, and `view()` hides the answer and authors until the reveal. A question's `decoys` power "Lie for me" (and strict-timeout fill-ins), worth half points, and pad a small board with house fakes that score for nobody. The last round counts double. Its `insights` feed the stats page (lies with how many they fooled, votes, rounds).
- **Masquerade's back-room edition** (`packages/private-games/masquerade-originals`, id `masquerade-originals`) reuses `defineMasquerade` with an ids-only pack: Edition 1 `e1-01`…`e1-30`, Edition 2 `e2-01`…`e2-20` (the host picks one or both). Names, art, coaching and question ideas come from the private `masquerade-originals/manifest.json` (`{ back?, editions?: { e1?: { name }, e2?: { name } }, locations: { "e1-01": { name?, art?, emoji?, tip?, questions?: string[] } } }`, art paths relative to the game's folder; location art is landscape 5:3, the back about 20:13, both shown with object-cover); without it, locations show as "Location 1"…"Location 50".
- **Royal Post** (`packages/private-games/royal-post`) plays both editions (Classic: 16 cards, 2 to 4 players; 2019: 21 cards, 2 to 6, with the Spy and Chancellor), chosen by the host. Code uses only the plain role ids (`spy`, `guard`, `priest`, `baron`, `handmaid`, `prince`, `chancellor`, `king`, `countess`, `princess`); card display names and art come from the private `royal-post/manifest.json` (`{ editions: { classic: { back, cards: { guard: { name, art } … } }, "2019": { … } } }`), with styled role-word placeholders when there is none. Never write the commercial game's name or publisher anywhere in the repo. `view()` sends only your own hand; Priest, Baron and King results go to a per-player private notes log.

- **Nightfall** (`packages/private-games/nightfall`) is a one-night hidden-role game, built for every set of its line and released in waves (wave 1: base, Daybreak, bonus packs 1 and 2; wave 2: the Vampire set; `ENABLED_SETS`). Never write the commercial game's name, publisher, narrator app or reference site anywhere in the repo.
  - **Ids in code, names from the manifest:** roles, sets and artifacts are plain kebab-case ids (`seer`, `alpha-wolf`, `paranormal-investigator`, `bonus1`, `claw-of-the-werewolf`). Display names, card text, portraits, narration clips and music come from the private `nightfall/manifest.json` (shape in `src/ui/assets.ts` and `docs/deployment.md`); without it, roles show as styled placeholders and the game is silent.
  - **Title from the database:** the game's real title is an admin setting (`private_game_titles` in `app_settings`, `PrivateGameSettings` in `apps/server/src/private-games.ts`, `/admin` or `scripts/set-game-title.mjs`), sent only to unlocked browsers (`/api/games`, `/api/rooms/:id`), falling back to "Nightfall". Any private game can use it, as it can the per-phase music override (`private_game_music`), which the back-room manifest endpoint merges into `music`.
  - **Engine:** `roles.ts` is the data registry (set, team, box count, how the Doppelgänger copies it), `plan.ts` the wake order (`STEPS`, sorted by the narrator's codes) and the narration keys, `night.ts` each role's action (`begin`/`prompt`/`act`), `resolve.ts` the vote and win rules (§3 of the rules research, with the user's rulings). Later sets add records, steps and hooks.
  - **Marks (Vampire set):** with any Vampire-set role but the Copycat (`MARK_ROLES`), every player gets a Mark of Clarity at the deal (`round.marks`, per player, not per card). Steps with negative `order` are the dusk: Fear (`feared`) only stops wakes from `NIGHT_ORDER` on. Players first see their own Mark in the `dusk` step (`mark` note), lovers meet in `lovers`; Marks reach `view()` only through the viewer's own notes until the reveal (tested with `JSON.stringify`). The vampires' Mark is one joint choice (the first pick counts for all). `resolveVote` takes the Marks: The Master's protection, Love chains (ignore protection), Disease (`disqualified`), the Traitor, the Assassins, Renfield's team and epic-battle places (`Death.place`).
  - **Night security:** every selected role gets a fixed-length step (complex roles double), even when its card is in the centre; steps never wait, and `onDeadline` makes mandatory choices at random. Players act as their dealt role. A non-acting player's `view()` changes only in the step counter and deadline (tested); the client derives the plan from the public roles, a tap on the shoulder arrives at daybreak, and the timeline is only revealed at the end.
  - **Sound:** the host picks narration Off / Host's device / Every device, plus background music; `src/ui/audio.ts` is the pure scheduling (cues on the server clock, track per phase, ducking, crossfades) and `useSound.ts` plays it after a user gesture. Text narration always shows.
  - **State:** `stage` is the real phase (`ready`, `night`, `day`, `vote`, `reveal`); `phase` is `playing`/`over` for the stats recorder. Its `insights` (all at the reveal) feed the stats page's figures, including `matrix` heatmaps, and fun facts.

## Conventions

- Never mention or link existing online party-game websites in code or docs. Ship self-authored word lists, never the official Codenames card list.
