# Defuse

Notes for working on this game. The repo-wide rules are in the root `CLAUDE.md`, including the shared patterns every back-room game follows; this file lists only what this game adds or does differently. Update this file in the same change as any rule, id or asset change.

## Rules and boundaries

- **Defuse** (`packages/private-games/defuse`, id `defuse`) is a bomb-defusal talking game for 2 to 12 seated: only the defuser's phone shows the bomb, only the experts' phones the manual. Never write its module or mod creators' names either.
  - **Follow the original's code:** every generator, timing and edge case is the decompiled original's (the class behind each is in the private BUILD-NOTES), quirks included. Module ids are `wires`, `button`, `keypad`, `simon`, `whos-on-first`, `memory`, `morse`, `complicated-wires`, `wire-sequence`, `maze`, `password`, `venting-gas`, `capacitor`, `knob`. The printed manual is `data.ts`; experts' pages are rebuilt from it in our own words.
  - **Manuals:** `generateRules(seed)` reproduces the original's generator (Mono's `System.Random` and quicksort); seed 1 is the printed manual (tested table for table). Players never see a seed; a bot defuser reads its bomb's manual from server memory.
  - **Clock:** everything is server time; `runTo(bomb, t)` plays every timed change in order from the bomb's hidden random stream (deadlines get no `rng`). A defuser's timed action carries `at`, judged then if at most 0.5 s back. One bomb is one game.
  - **`view()`:** the defuser gets the bomb as it shows and never the manual's answers; experts and watchers nothing of the bomb (the clock and strikes only with the host's option); the table screen the manual or, with "Bomb", the defuser's bomb.
  - **Table screen:** the shared poster for the lobby, the result and the manual setting, which shows who reads which page (a large slate per expert over a faint manual cover, "No page yet" until they claim one) and the clock (when the host shows it), never the pages (owner: they stay on the experts' phones); with "Bomb" it shows the bomb full screen, inert (nothing on it can be pressed), its 2D face labels at 24 px.
  - **The 3D bomb and room** (`src/ui/three/`, three.js pinned): built from the private scene and room packs the manifest names (never from a CDN); `look.ts`, `controls.ts`, `glance.ts` and `room.ts`'s `roomLook` are pure and tested. Without the packs every node is a plain box, so the game and its e2e still run. Players may pick the flat 2D view instead. In test mode the view carries `test` and the 3D view offers `window.__defuse3d` hooks for `e2e/defuse-3d.spec.ts`.
  - **Bots:** a bot defuser solves what its view shows after 6–20 s a module, wrong about one move in eight (`ponder`); bot experts only claim a page.
  - **Testing:** `DEFUSE_TEST_SEED` builds every bomb (and different manual) from one seed; `DEFUSE_TEST_LIGHTS` replaces room surprises with lights out at a fixed time.

- **UI:** the experts' manual page reads inside its own bounded panel on every screen (phones 52% of the height; wide screens the height left under the page's title, claim line and notes), and on wide screens the page index rail scrolls inside too, so an expert's screen never scrolls and the claim and notes stay in view.

## Assets

**Defuse** (`node scripts/r2-upload.mjs defuse <folder>`, dry-run first): renders of the original's own models, front-on, with every interactive part as its own layer: each module's `modules/<kind>/face.webp` (+ `face@2x.webp`) and its parts (`wire-<n>-<colour>[-cut]`, `button-<colour>`, `strip-<colour>`, `status-off|pass|strike`, `key-<n>`, `led-<n>-…`, `pad-<place>-on|off`, `stage-<n>-on|off`, `dial-<dir>`, `knob-<dir>`…), each the module's full canvas with transparency; the casing's faces and edges (`casing/<front|rear|top|bottom|left|right|blank>/`), the timer (`timer/`), the widgets (`widgets/`), the 31 keypad glyphs (`glyphs/<n>.webp`), the manual's page images (`manual/page-NN.webp` + thumbs), the stamps, the fonts (`fonts/`) and the sounds and music (`audio/sfx/`, `audio/music/`), with a `manifest.json` of the form `{ "names": { "modules": { "wires": "…", … }, "missions": { "s1-1": { "name", "description" }, … }, "sections": { "1": "…", … } }, "casing": { "front": { "art", "thumb" }, … }, "timer": { "backing", "size", "parts", "defaults" }, "modules": { "<kind>": { "base", "size": [w, h], "parts": { "<part>": { "art", "box": [x, y, w, h] } }, "defaults": { "<layer>": "<part>" }, "anchors"?, "glyphBoxes"?, "grid"?, "dialCentre"? } }, "widgets": { … }, "glyphs": { "1": …, … }, "manual": { "pages": { "1": …, … }, "modulePages": { "wires": [5], … } }, "stamps", "fonts": { "digits", "labels", "morse", "manual" }, "audio": { "effects": { "<file stem>": "…" | […] }, "music": { "game-a": […], …, "gameover-win", "gameover-lose" } }, "extras": { "casingSlots", "casingAreas", "portBoxes" }, "credit": … }` (shape in `packages/private-games/defuse/src/logic/manifest.ts`; part ids are the model's part names, so a 3D view can map them back; keep the exported meshes and textures with the private art). The 3D bomb (the default defuser view) is the `3d/` folder, named by the manifest's `"scene": "3d/"`: `3d/scene.json` (the prefabs as node trees), `3d/scene.bin` (their geometry), `3d/tex/<name>.hi.ktx2` and `.lo.ktx2` (GPU-compressed textures, full and half size) with `.jpg`/`.png` fallbacks of the same names, and `3d/basis/basis_transcoder.js` + `.wasm` (copied from the pinned `three` package's `examples/jsm/libs/basis/`; the browser never fetches them from a CDN). `r2-upload.mjs` sends `.ktx2`, `.bin`, `.wasm` and `.js` with their types. Without `scene` the 3D bomb is drawn as plain boxes. Every field is optional: without the manifest, the bomb is plain styled panels and words and the game is silent. Once it is uploaded, set the title with the `defuse` id.
