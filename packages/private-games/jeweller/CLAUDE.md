# Jeweller

Notes for working on this game. The repo-wide rules are in the root `CLAUDE.md`, including the shared patterns every back-room game follows; this file lists only what this game adds or does differently. Update this file in the same change as any rule, id or asset change.

## Rules and boundaries

- Seat changes accept only own entries in the seat map and reject prototype keys before mutation.

- **Jeweller** (`packages/private-games/jeweller`, id `jeweller`) is a gem-merchant card game for 2 to 4, with its Cities and Strongholds modules (host options, combinable).
  - **Ids:** the 90 cards (`L1-01`…`L3-20`) and 10 nobles (`N01`…`N10`) are the table in `src/logic/cards.ts`; gems are `white`/`blue`/`green`/`red`/`black` plus `gold`; Cities are sides `C1a`…`C7b` (`src/logic/cities.ts`). The UI draws every card's points and cost itself, so art is only a backdrop.
  - **Rules (the owner's rulings):** the app pays gems before gold (`payment()`, editable); pass only when nothing at all is legal, and a full round of passes ends the game as it stands (`how: 'stalled'`); with Cities, only players meeting a City can win. Strongholds open the `hold` stage after every purchase, before the emptied spaces refill, and a full set on an affordable card offers a Conquest (`conquer` stage). Safe moves never make a Conquest.
  - **`view()`:** reserved cards are a hand (others see the count and level; the host's "show reserved cards" shows those reserved face up, never a deck's top), and the reserve log names the card only to whoever may see it.
  - **Testing:** `JEWELLER_TEST_DECK` (e.g. `1:L1-35;n:N09;own:L3-05;c:C3a;h:L1-35`) stacks decks, nobles, owned cards, City sides and strongholds, with the first seat starting.
  - **Phones:** Table (market and piles), Your table and Table talk (log, players, host tools) on the shared `TabBar`; the turn's bar (piles, Take, hand-back, nobles, holds, Conquest) is the fixed `StickyBar` with `jw-play`. First-time tips are a closed fold on phones.

- **UI:** The market fills the main desktop column; players and log share one rail. Market cost pips grow on desktop.

## Assets

**Jeweller** (`node scripts/r2-upload.mjs jeweller <folder>`, dry-run first): the 90 card faces in `cards/` (by card id, `cards/L1-01.webp`…, with optional small copies for the market on phones), each level's deck back in `backs/`, the 10 nobles in `nobles/`, the six piece faces in `tokens/`, `box` and `logo` pictures, and a `manifest.json` of the form `{ "title": "…", "cards": { "L1-01": "cards/L1-01.webp" | { "art", "thumb" }, … }, "backs": { "l1", "l2", "l3" }, "backThumbs": { … }, "nobles": { "N01": "nobles/N01.webp" | { "art", "name" }, … }, "tokens": { "white", "blue", "green", "red", "black", "gold" }, "tokenThumbs": { … }, "cities": { "C1a": "cities/C1a.webp" | { "art", "thumb" }, … }, "strongholds": ["strongholds/blue.webp", …], "box": "…", "logo": "…", "guide": { "tagline" }, "credit": "…" or { "title", "paragraphs": […], "links": [{ "label", "href" }] } }` (shape in `packages/private-games/jeweller/src/logic/manifest.ts`; card ids `L1-01`…`L3-20` and noble ids `N01`…`N10` are in `src/logic/cards.ts`). The app draws every card's points and cost itself, so the art is a backdrop and a printed cost never needs to be read. The Cities module's 14 tile sides (`C1a`…`C7b`, landscape 2:1, the printed points and cards are read from the art, so the full side is shown) go in `cities/`, and the Strongholds pieces (one picture per colour, named `blue`, `red`, `green` and `orange` (`strongholds/red.webp`), else taken in that order; a player whose room colour is one of them gets those, the others get the colours left in turn order; about 100 px, shown small on cards) in `strongholds/`. Every field is optional: without the manifest, cards are drawn from their numbers, pieces are coloured chips, nobles are numbered, City sides are drawn from their numbers and strongholds show as 🏰. Once it is uploaded, set the title with the `jeweller` id.
